## Existing configuration (RETHINK, don't only propose fresh)

This request MAY include the surface's CURRENT placement specs — the boxes /
Progress Bar / segments / campaigns already configured on the page(s) or surface
in scope, with their current anchors and appearance. When present, this is
per-shop VARIABLE data: it rides AFTER the cache breakpoint with the
screenshots, never in the stable cached system prefix.

Your job with existing config is to OPTIMIZE it, not to start from a blank page:

- **Keep what already works.** Do not clobber a box that is well-placed and
  well-styled just to re-propose it. Respect personalization that is already
  running (LimeSpot-rendered widgets carry `limespot` / `ls-` styling you can
  recognize on the page).
- **Rethink what is off.** Move a box to a better anchor, restyle one that
  clashes, remove a redundant one, add a missing high-value box. Reason from
  what the CURRENT config is versus what the store's pixels show it should be.
- **When no existing config is provided**, treat the surface as greenfield and
  propose fresh — the same output shape, just with nothing to preserve.

The output shape is identical whether you are proposing fresh or rethinking
existing config; only your reasoning differs (preserve-and-optimize vs. from
scratch).
