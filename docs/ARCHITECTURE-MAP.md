# Architecture map — app-ai

**Parent:** [../CLAUDE.md](../CLAUDE.md)

The folder-by-folder map of `src/`: what each module owns, read on demand. The INVARIANTS this
layout exists to hold are in the root [CLAUDE.md](../CLAUDE.md) → Architecture; each folder's own
rules are in its `CLAUDE.md` ([handlers](../src/handlers/CLAUDE.md), [lib](../src/lib/CLAUDE.md),
[toolsets](../src/toolsets/CLAUDE.md), [prompts](../src/prompts/CLAUDE.md)). The tree below names
modules and their responsibility; a module's exact exports and signatures are read from the module
itself, never restated here.

```
src/
├── index.ts              # Entry + router only: CORS, OPTIONS, context-ID auth, dispatch
├── config.ts             # Typed `Env` + fail-fast config accessors — the ONE place bindings are read
├── types/markdown.d.ts   # Ambient module type: `.md` imports resolve to their raw text
├── handlers/             # Route handlers (see handlers/CLAUDE.md)
│   ├── health.ts         # GET  /health (no auth)
│   ├── files.ts          # POST/GET /files, DELETE /files/{id}
│   ├── messages.ts       # POST /messages — single-shot proxy (LIVE smart-image)
│   ├── chat.ts           # POST /chat — Studio AI agent loop + SSE
│   └── demo-session.ts   # POST /demo/session/exchange — one-time activation exchange
├── lib/                  # Shared modules (see lib/CLAUDE.md)
│   ├── anthropic.ts      # THE Anthropic client: files + messages + streaming + countTokens (headers/beta in one place)
│   ├── auth.ts           # validateContextId() against Personalizer
│   ├── demo-auth.ts      # Scoped demo JWT validation + request reservations
│   ├── demo-session-authority.ts # Durable Object: stable audit attempts, quotas, files, callback outbox
│   ├── demo-audit-status.ts      # HMAC-signed website status callback transport
│   ├── cors.ts           # getCorsHeaders()
│   ├── responses.ts      # jsonResponse() / errorResponse() / errorPayload() / WorkerError — the ONE Brain-shaped error format
│   ├── cache-control.ts  # manageCacheControl() — the 4-block prompt-cache limit + explicit stable user-prefix priority; EXTENDED_CACHE_CONTROL (1h TTL) const
│   ├── agent-cache.ts    # applyConversationBreakpoints() — cache breakpoints on /chat conversation turns (≤3, ~15-block intervals)
│   ├── file-dedup.ts     # dedupUpload() / sha256Hex() — Files API contentHash→file_id dedup (KV-backed LIVE, stale-id verify, 30d TTL, graceful no-op)
│   ├── references.ts     # /chat context.refs intake + the Referenced-Entities system block (record refs → the personalizer toolset's entity-context.ts; analytics refs → own metadata)
│   ├── dev-inference-trace.ts # Correlated /messages + /chat model/tool trace routed at TRACE level
│   └── logger.ts         # Request-scoped structured logger; LOG_TARGETS_* fan-out to console/Seq
├── toolsets/             # The AI-tool layer: named toolsets + registry (see toolsets/CLAUDE.md + docs/TOOLSETS.md)
│   ├── registry.ts       # composeToolsets(...) — capability-filtered per-request composition, tool-name routing, credential seam
│   ├── integration-party.ts # IntegrationParty — verbatim mirror of Personalizer's C# enum (wire NAMES); the single identity gating composition + keying the bridge URL segment
│   ├── types.ts          # The toolset seam types: ToolsetDescriptor (name / integrationParties / definitions / …) / ToolsetComposition / ToolExecution
│   ├── integration-bridge.ts # Shared platform-toolset plumbing: call-channel seam (context-ID + PERSONALIZER_INTEGRATION_BRIDGE_TOKEN → Personalizer's v2/integration-bridge/{party}) + REST/GraphQL/GAQL executors (GAQL: PageSize?/PageToken?) + the X-Ls-Integration-Bridge-Error discrimination
│   ├── personalizer/     # Every tool whose backend is the Personalizer API
│   │   ├── index.ts      # Toolset descriptor: frozen tool definitions + /v2/ai-tools/* dispatch + get_entity_context dispatch + degrade shape
│   │   └── entity-context.ts # fetchEntityContext() — record-ref resolution: per-refType fetchers over Personalizer's per-record admin endpoints → the frozen AiToolEntityContext shape
│   ├── shopify/          # Shopify platform toolset: shopify_rest_request (version-less Admin REST) + shopify_graphql (verbatim documents, mutations included)
│   ├── bigcommerce/      # BigCommerce platform toolset: bigcommerce_rest_request (version-prefixed v2/…/v3/… paths)
│   ├── klaviyo/          # Klaviyo platform toolset: klaviyo_rest_request (api/… paths, JSON:API paging via query params)
│   └── google-ads/       # Google Ads platform toolset: google_ads_gaql_query (GAQL SELECT via the google/gaql proxy surface — read-only by nature)
├── prompt-registry.ts    # System-prompt REGISTRY: name → { prompt, tier, maxTokens, usesTools, description, attachments }; reads text via the src/prompts/ barrel
├── prompts/              # The prompt TEXT layer (one location — pure .md, bundled at build time)
│   ├── index.ts          # Barrel: imports every prompt's .md (and assembles the composed prompts) and re-exports each prompt's FINAL text as a named export the registry reads
│   ├── _compose.ts       # composePrompt(...parts) — joins ordered block strings into one composed system prompt
│   ├── *.md              # SIMPLE prompt TEXT (one .md per prompt)
│   ├── <name>/           # MULTI-FILE prompt (folder): prompt.md (system) + sample.md (attachment)
│   └── <name>/index.ts   # COMPOSED prompt: its own barrel assembles the prompt from _-prefixed block fragments + onboarding-shared/ blocks via composePrompt
```

## `src/handlers/` — route handlers

One handler per route group, each returning a `Response`. `src/index.ts` is the source of truth for which path reaches which handler; the routes named below are that map read from the handler side.

| File              | Route(s)                                          | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `health.ts`       | `GET /health`                                     | Liveness check. No auth, no Anthropic call. Returns `buildRev` — the EXACT served revision from `src/build-rev.ts` (esbuild `--define __APP_AI_REV__`, injected by `npm run dev`, `npm run deploy`, `npm run deploy:preview`, and `npm run deploy:dry-run` from `git rev-parse --short HEAD`). A define-less local/test build reports `'dev'`; a define-less production build fails health closed with 503 `UnattributableBuildException`. The FREE-stack preflight (`onboarding-fork-matrix`) asserts the marker is present + non-`'dev'` (C0014 item 14).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `demo-session.ts` | `POST /demo/session/exchange`                     | Exchanges one email-verified, website-signed activation JWT for an app-ai-signed `ls_demo_…` bearer session. The handler validates JSON input and delegates signature, one-time consumption, origin binding, and lifetime enforcement to `lib/demo-auth.ts` plus `DemoSessionAuthority`. No Context-ID or Brain call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `files.ts`        | `POST /files`, `GET /files`, `DELETE /files/{id}` | Proxy to the Anthropic Files API. Upload routes through content-hash dedup (`lib/file-dedup.ts`) so identical bytes reuse a `file_id`; response shape stays `{ id, type }`. Success responses proxy as-is; failures return the Brain-shaped error envelope (missing file → 400 `ArgumentException`; Anthropic failures keep the upstream status as `AnthropicApiException` with the raw body in `MessageDetail`; 500 upload errors also get the beta-access hint in `Message`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `messages.ts`     | `POST /messages`                                  | Single-shot Messages proxy — the **LIVE smart-image** surface. Enforces the onboarding ruleset-version handshake (`validateRulesetVersion`, 409 on a supplied incompatible `X-Personalizer-Ruleset-Version`, fail-OPEN when absent), injects the registry system prompt, uploads attachments (dedup), sets `model` + `max_tokens` EXACTLY from the registry entry (registry authoritative — no client override / floor / cap), for an `injectsBrainDefaults` PROPOSE prompt fetches+projects the global Brain default box settings (page -> box, effective appearance inheritance) and injects them as a SECOND cacheable system block (`lib/brain-defaults.ts`), and manages the 4-block `cache_control` limit. A first-message block marked `limespot_stable_cache_prefix: true` receives the priority 1h breakpoint after system/attachment accounting; the internal marker is stripped before forwarding and blocks/file IDs are not reordered. The handler then applies opt-in `effort`; latency-critical visual/onboarding prompts proceed directly to inference, while other large payloads may run the best-effort advisory `count_tokens` pre-flight. In demo mode it keeps only the prevalidated evidence message, requires the ruleset header, forces registry model/budget/effort, skips Brain-default injection, and ignores caller tools/provider knobs. Success bodies flow through unchanged; a non-ok Anthropic response returns the Brain-shaped envelope with Anthropic's status (`AnthropicApiException`, raw body in `MessageDetail`).                                           |
| `chat.ts`         | `POST /chat`                                      | Studio AI agent loop + SSE. Runs the Anthropic tool-use loop (`MAX_ITERATIONS=8`) against the tool surface composed per request from the toolset registry (`../toolsets/registry.ts`) using the validate-context-id response's available integration parties and version-gated AI-tool names. The four Personalizer data tools require exact advertised names; `get_entity_context` remains independent; platform toolsets require their parties. Streaming `text`/`tool_call`/`tool_result`/`done`/`error` events; non-streaming clients get the `done` payload as JSON. `fileIds` become `image`/`document` blocks (typed by Files-API mime), with a 1h cache breakpoint on the file prefix (placement screenshot + HTML). `context.refs` (entity references, cap 5 — `lib/references.ts`) are sanitized, eagerly prefetched, rendered as the UNCACHED final Referenced-Entities system block, and threaded into the agent loop for `get_entity_context`'s analytics dispatch; requests without refs send a system array identical to a refs-free build (cache safety). **Also carries a LIVE CLIENT-tool mode** (first consumer: the `onboarding-chat` prompt): a prompt whose registry entry sets `clientTools` sends THOSE definitions to the model in place of the server toolset, and on a `tool_use` returns the calls to the client in `done.toolCalls` (`stopReason: 'tool_use'`) and STOPS the turn — the worker executes nothing and makes no Brain proxy call; the client (the lib) runs the tools (`look_at_page` → a store screenshot) and calls `/chat` again with the `tool_result`. |

## `src/lib/` — shared modules

What each shared module owns. A module's exported surface is read from the module itself — every export there carries a doc comment, so a list of them here would only drift.

| File                        | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `anthropic.ts`              | The ONE place that talks to `api.anthropic.com`. Owns base URLs, `anthropic-version`, beta flags, and `x-api-key` injection. `getFileMetadata(id)` GETs `/v1/files/{id}` (200 alive / 404 gone) — used by dedup to verify a cached id before reuse and by `chat.ts` to type file blocks by mime. `supportsEffort(model)` is the effort-capability gate over the `EFFORT_SUPPORTED_MODELS` set declared beside it — the only place that set is written down; handlers call it before attaching `output_config.effort` so an unsupported model never 400s.                                                                                                                                                                                                                                                                                                     |
| `auth.ts`                   | Validate `X-Personalizer-Context-ID` server→server against Personalizer. Throws a `WorkerError` on any failure: missing header → 401 `MissingContextIDException`; a Personalizer rejection carries Personalizer's status + body for verbatim passthrough; an unreachable Personalizer → 500 `BrainUnreachableException`. On success resolves the consumed `ContextValidation` members, including `AiToolsContractVersion`, `AvailableAiTools`, and `AvailableIntegrationParties`; the router threads the supported capability sets into `/chat` without another call or cache.                                                                                                                                                                                                                                                                               |
| `demo-auth.ts`              | Demo bearer-token boundary. Verifies website activation JWTs with the activation key, consumes each once, issues app-ai-only `ls_demo_…` sessions with a separate key, matches the extension-supplied active-tab origin to the signed store origin, allowlists four onboarding upload destinations plus the two proposal inference prompts, validates message/file shapes and byte limits, and reserves/finalizes usage through `DemoSessionAuthority`. Non-demo bearer values fall through to normal Context-ID auth.                                                                                                                                                                                                                                                                                                                                       |
| `demo-session-authority.ts` | Strongly consistent state keyed by the stable signed audit identifier. It consumes activation identifiers exactly once, permits one live browser session, preserves public completed-attempt counts across reissued links, serializes concurrent quota/file ownership changes, and owns the ordered callback outbox. Failed inference releases the same attempt number; only successful proposal inference increments the public cap. Expiry clears provider file IDs and per-session counters while retaining the minimal audit ledger/replay set/outbox.                                                                                                                                                                                                                                                                                                   |
| `demo-audit-status.ts`      | Signs immutable `started`/`completed`/`failed` JSON events with the distinct callback key and posts them to the exact website status endpoint. Only a 2xx lets the Durable Object remove the head event; failures remain retryable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `cors.ts`                   | Build CORS headers from the request Origin. Echoes any merchant Origin without credentials; the `CREDENTIALED_ORIGINS` config variable (parsed by `../config.ts`) allowlists the dev origins that may send credentialed requests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `responses.ts`              | The ONE error format: Brain's wire shape (`{ Message, ExceptionType, MessageDetail? }`, flat PascalCase, `MessageDetail` omitted when absent) — app-ai errors are structurally identical to Brain errors so clients keep one parser. `WorkerError` pins status/`ExceptionType`/detail at the throw site (and `passthroughBody` relays a forwarded Brain error verbatim); `errorResponseFrom` maps any caught error to the envelope; `anthropicErrorResponse` wraps a non-ok Anthropic body (`AnthropicApiException`, upstream status kept, raw body in `MessageDetail`).                                                                                                                                                                                                                                                                                     |
| `cache-control.ts`          | Keep `/messages` within Anthropic's 4-block `cache_control` limit; the 1h extended-TTL breakpoint const for stable prefixes. Counts the actual cached system and attachment blocks, strips unmanaged client breakpoints outside the proxy-owned attachment prefix, gives a caller-marked terminal stable user-prefix block priority over normally ranked user images/documents, strips the internal `limespot_stable_cache_prefix` marker before Anthropic forwarding, and preserves content order/file IDs.                                                                                                                                                                                                                                                                                                                                                 |
| `brain-defaults.ts`         | Global defaults provider for the PROPOSE prompts (`injectsBrainDefaults` entries). Fetches canonical Brain `RecommendationsSettings` (`GET ${PERSONALIZER_API_URL}/v1/personalizerConfig?defaultRecommendationsSettings=true`, forwarding the context-ID; or a configured CDN URL via `recommendationsDefaultsUrl`, fetched without the context-ID), projects only the AI-relevant fields while preserving page -> box hierarchy and desktop/mobile inheritance, and emits compact byte-stable canonical JSON. One global in-isolate promise/result coalesces cold requests and keeps a successful block for the isolate; a cold failure skips injection and remains retryable. There is no defaults-version protocol. `messages.ts` injects the stable block as a second cacheable system block after the registry prompt and before per-store screenshots. |
| `agent-cache.ts`            | Place cache breakpoints on the growing `/chat` conversation turns (last block + ~every-15-blocks), re-stripped each iteration. `maxBreakpoints` (default 3) + `reservedHeadBlocks` (protects the placement file prefix's own 1h breakpoint) keep the total ≤4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `file-dedup.ts`             | Files API content-hash dedup: SHA-256 → `file_id` via the `FILES_KV` binding (bound in prod → LIVE). Verifies a cached id still exists before reuse (stale → re-upload); records carry a 30-day TTL. Graceful no-op (plain upload) when KV is unbound.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `references.ts`             | Chat referencing (`context.refs`, frozen contract in lib CONTRACTS.md §1/§8). Intake sanitizer (valid type literals only, record refs need an `id`, cap 5 — first five kept) + the eager Referenced-Entities system block: every surviving ref resolves concurrently via `Promise.allSettled` (record types → `fetchEntityContext`, the personalizer toolset's normalizer in `../toolsets/personalizer/entity-context.ts`, sharing ONE subscriber lookup per block build; analytics types → the ref's own `metadata`, NO Personalizer call); a failed resolve degrades that ref's line to `(could not load)` — the block never throws. The block text is a frozen format: `## Referenced Entities` heading + preamble + one `- [<type>] "<label>" (<anchor>): <payload>` line per ref.                                                                       |
| `dev-inference-trace.ts`    | Structured inference trace producer. Correlates complete model-visible `/messages` and each `/chat` agent-loop turn—including file references—with assistant output, client/server tool decisions, execution results, completion/failure, and elapsed time. Emits at TRACE through the request logger, so deployment configuration owns all sink policy.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `logger.ts`                 | Request-scoped structured logging runtime. Parses every `LOG_TARGETS_*` route once, fans each record to zero/one/multiple registered sinks, delivers CLEF asynchronously to Seq with optional `LOG_SEQ_API_KEY`, captures background rejections, preserves error stacks/causes/details and context IDs, redacts actual secret-bearing fields, and keeps sink failures fail-open/non-recursive. The Console sink is the only Worker source allowed to call `console.*`.                                                                                                                                                                                                                                                                                                                                                                                       |

What each toolset module owns. A module's exported surface is read from the module itself; the descriptor contract every toolset implements is in [TOOLSETS.md](TOOLSETS.md).

| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `registry.ts`                    | Compose the active toolsets for one request from available `IntegrationParty` values, version-gated AI-tool names, `{ contextId, env }`, and the request logger. Party gates select descriptors; optional `selectDefinitions` filters their model-visible definitions. Each gated toolset's single matched party reaches `execute` as `matchedParty`. Routes each `tool_use` to the owner; a gated-off, capability-filtered, or unowned name degrades to `Unknown tool`. Resolves credentials lazily per composition and throws on cross-toolset name collisions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

| `integration-party.ts`           | Verbatim mirror of Personalizer's C# `IntegrationParty` enum (member NAMES; the wire form, never the guid). The single identity keying composition: descriptors gate on it, validate-context-id returns the available set, the executor builds the bridge URL segment from the matched party. v1-active: `ShopifyPersonalizer`, `BigCommercePersonalizer`, `Klaviyo`, `Google`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `integration-bridge.ts`          | Shared plumbing behind the platform toolsets. `resolveBridgeChannel({ contextId, env })` is every platform toolset's credential seam — it resolves the CALL CHANNEL toward Personalizer's integration bridge (`{ contextId, serviceToken, baseUrl }` via the `personalizerIntegrationBridgeToken` / `personalizerApiUrl` accessors in `src/config.ts`; app-ai never holds a platform token), thrown failures degrade via the registry. The executors map tool input onto the bridge wire shapes, where `{party}` is the matched `IntegrationParty` name (`{verb} v2/integration-bridge/{party}/rest/{path}?{query}` with JSON POST/PUT bodies and body-less DELETE; `POST …/{party}/graphql` with `{ Query, Variables? }`; `POST …/{party}/gaql` with `{ Query, PageSize?, PageToken? }` — PascalCase, Personalizer's request models; the GAQL response `NextPageToken` surfaces verbatim so the model pages by echoing it back), send both channel headers (`X-Personalizer-Context-ID` + `X-Personalizer-Integration-Bridge-Token`), and discriminate responses by the `X-Ls-Integration-Bridge-Error` header: absent → the platform speaking, surfaced verbatim as `{ ok: true, result: { platformStatus, headers?, body } }` at ANY status (platform 4xx/5xx are data the model self-corrects on; `headers`, lowercased keys, is the whitelisted out-of-band subset — `Link` for Shopify REST `page_info` cursors, `Retry-After`, the platform rate-limit headers — omitted when none are present); present → the LimeSpot `{ Message, ExceptionType }` envelope, degraded to `{ ok: false, result: { error: '<Message> (<ExceptionType>)' } }`. Dispatches through `integration-bridge.ts` onto the `bigcommerce` proxy segment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `klaviyo/index.ts`               | Klaviyo platform toolset (`klaviyo_rest_request` — `api/…` paths; JSON:API paging is body-native, cursors follow via the `page[cursor]` query param). Dispatches through `integration-bridge.ts` onto the `klaviyo` proxy segment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `google-ads/index.ts`            | Google Ads platform toolset (`google_ads_gaql_query` — GAQL SELECT against the merchant's linked ads account, which Personalizer resolves itself; read-only by nature of GAQL). Dispatches through `integration-bridge.ts` onto the `google` proxy segment (gaql surface).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `personalizer/index.ts`          | The personalizer descriptor and frozen definitions. The four `/v2/ai-tools/*` data tools are filtered to supported-contract capabilities and re-checked before dispatch; `get_entity_context` is independent. Brain calls forward the context-ID, validate required success members, retain raw failures only in operational logs, and return generic model-visible degrades. Record entity context delegates to `entity-context.ts`; analytics context resolves from request refs without Personalizer.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `personalizer/entity-context.ts` | The personalizer toolset's normalizer: record-ref resolution for every `RECORD_REF_TYPES` member → the frozen model-visible `AiToolEntityContext` shape declared in this module, with null members omitted and a miss collapsing to a not-found record; member order and omission are pinned by `test/entity-context.test.ts`. Per-type fetcher table over Personalizer's per-record admin endpoints, forwarding the context-ID: campaign probes discount → html → image (`v2/discount-campaigns/discount-campaign/{guid}` → `v2/html-campaigns/html-campaign/{guid}` → `v1/imageCampaigns?guid=`), segment → `v1/subscriberSegment?guid=`, progress-bar → `v2/progress-bar-campaigns/{guid}`, bundle → the discount route with a bundle-flavored Summary. Every resolution also loads `v2/accounts/subscriber` (memoizable via the optional `shared` param): its Guid is the tenant re-check on every loaded entity, its CurrencyCode fills the progress-bar `Currency` field. Discount/bundle `Related` = one-hop targeted segments via per-guid `v1/subscriberSegment` loads (tenant-checked, non-deleted). Misses (404/204/5xx/cross-subscriber/deleted) → `Found: false`; malformed guid, unknown type, subscriber-lookup failure, 401/403, network failure → throw (callers degrade). Also consumed by `lib/references.ts` for the eager Referenced-Entities block. No extra context-ID validation call — Personalizer re-validates the forwarded header on every proxied call.                                                                                                                                                                                                                      |
