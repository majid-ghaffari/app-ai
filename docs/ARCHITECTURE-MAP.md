# Architecture map — app-ai

**Parent:** [../CLAUDE.md](../CLAUDE.md)

The folder-by-folder map of `src/`: what each module owns, read on demand. The INVARIANTS this
layout exists to hold are in the root [CLAUDE.md](../CLAUDE.md) → Architecture; each folder's own
rules are in its `CLAUDE.md` ([handlers](../src/handlers/CLAUDE.md),
[inference](../src/inference/CLAUDE.md), [lib](../src/lib/CLAUDE.md),
[toolsets](../src/toolsets/CLAUDE.md), [prompts](../src/prompts/CLAUDE.md)). The tree below names
modules and their responsibility; a module's exact exports and signatures are read from the module
itself, never restated here.

## `src/handlers/` — route handlers

One handler per route group, each returning a `Response`. `src/index.ts` is the source of truth for which path reaches which handler; the routes named below are that map read from the handler side.

| File               | Route(s)                            | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `health.ts`        | `GET /health`                       | Liveness check. No auth, no Anthropic call. Returns `buildRev` — the EXACT served revision from `src/build-rev.ts` (esbuild `--define __APP_AI_REV__`, injected by `npm run dev`, `npm run deploy`, `npm run deploy:preview`, and `npm run deploy:dry-run` from `git rev-parse --short HEAD`). A define-less local/test build reports `'dev'`; a define-less production build fails health closed with 503 `UnattributableBuildException`. The FREE-stack preflight (`onboarding-fork-matrix`) asserts the marker is present + non-`'dev'` (C0014 item 14).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `prompts.ts`       | `GET /prompts`                      | MASTER-gated routing diagnostics. After ordinary context-ID validation it requires the resolved `SubscriberID` to equal `MASTER_SUBSCRIBER_ID`, and answers any other validated merchant with the router's unknown-route body byte for byte. The one route reading its context-ID from either the `X-Personalizer-Context-ID` header or a `personalizerContextId` query parameter — this module owns the parameter name and its only reader, the header wins when both are present, and the URL form is an operator convenience whose credential browser history and URL-recording intermediaries see, so automation sends the header. Reports each registered prompt's group, tier, resolved model/provider/API family/file policy, declared capability requirements, and whether the route validates (with the reason when it does not), plus the NAMES of required secrets still blank — never a value, prefix, or length. Runs no inference.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `audit-session.ts` | `POST /audit/session/exchange`      | Exchanges one email-verified, website-signed activation JWT for an app-ai-signed `ls_audit_…` bearer session. The handler validates JSON input and delegates signature, one-time consumption, origin binding, and lifetime enforcement to `lib/audit-auth.ts` plus `AuditSessionAuthority`. No Context-ID or Brain call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `files.ts`         | `POST /files`, `DELETE /files/{id}` | Prompt-aware direct upload surface over the adapter factory. POST requires one or more registered `prompt` parts, validates every destination and the sealing configuration, resolves and collapses routes, uploads each distinct route through content-hash dedup (`lib/file-dedup.ts`) so identical bytes reuse a `file_id`; the response is one reference (`{ id, type }`) plus a `references` map naming every declared prompt, with same-route prompts sharing one reference. DELETE resolves the provider and upstream object id out of the sealed reference, refusing one from another tenant (403) or one whose route has since been configured onto another provider (409). No verb enumerates a provider account, because one account holds every tenant's uploads. Success responses proxy as-is; failures return the Brain-shaped error envelope (missing file → 400 `ArgumentException`; Anthropic failures keep the upstream status as `AnthropicApiException` with the raw body in `MessageDetail`; 500 upload errors also get the beta-access hint in `Message`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `messages.ts`      | `POST /messages`                    | Single-shot registered-prompt inference (`image-selection`, the probes, and the onboarding / cart-drawer / optimize prompts). Enforces the onboarding ruleset-version handshake (`validateRulesetVersion`, 409 on a supplied incompatible `X-Personalizer-Ruleset-Version`, fail-OPEN when absent), injects the registry system prompt, uploads attachments (dedup), sets `model` + `max_tokens` EXACTLY from the registry entry (registry authoritative — no client override / floor / cap), for an `injectsBrainDefaults` PROPOSE prompt fetches+projects the global Brain default box settings (page -> box, effective appearance inheritance) and injects them as a SECOND cacheable system block (`lib/brain-defaults.ts`), and manages the 4-block `cache_control` limit. A first-message block marked `limespot_stable_cache_prefix: true` receives the priority 1h breakpoint after system/attachment accounting; the internal marker is stripped before forwarding and blocks/file IDs are not reordered. The handler then applies opt-in `effort`; latency-critical visual/onboarding prompts proceed directly to inference, while other large payloads may run the best-effort advisory `count_tokens` pre-flight. In audit mode it keeps only the prevalidated evidence message, requires the ruleset header, forces registry model/budget/effort, skips Brain-default injection, and ignores caller tools/provider knobs. Success bodies use the established messages envelope. Non-ok provider responses preserve their status and provider exception type; malformed provider output is a provider-specific 500. The protected Cloudflare verdict additionally validates its frozen JSON before success. |
| `chat.ts`          | `POST /chat`                        | Studio AI agent loop + SSE. Runs the provider-neutral tool-use loop (`MAX_ITERATIONS=8`) against the tool surface composed per request from the toolset registry (`../toolsets/registry.ts`) using the validate-context-id response's available integration parties and version-gated AI-tool names. The four Personalizer data tools require exact advertised names; `get_entity_context` remains independent; platform toolsets require their parties. Streaming `text`/`tool_call`/`tool_result`/`done`/`error` events; non-streaming clients get the `done` payload as JSON. `fileIds` become `image`/`document` blocks (typed by Files-API mime), with a 1h cache breakpoint on the file prefix (placement screenshot + HTML). `context.refs` (entity references, cap 5 — `lib/references.ts`) are sanitized, eagerly prefetched, rendered as the UNCACHED final Referenced-Entities system block, and threaded into the agent loop for `get_entity_context`'s analytics dispatch; requests without refs send a system array identical to a refs-free build (cache safety). **Also carries a LIVE CLIENT-tool mode** (first consumer: the `onboarding-chat` prompt): a prompt whose registry entry sets `clientTools` sends THOSE definitions to the model in place of the server toolset, and on a `tool_use` returns the calls to the client in `done.toolCalls` (`stopReason: 'tool_use'`) and STOPS the turn — the worker executes nothing and makes no Brain proxy call; the client (the lib) runs the tools (`look_at_page` → a store screenshot) and calls `/chat` again with the `tool_result`.                                                                                                            |

## `src/inference/` — the provider-neutral runtime

Handlers construct canonical requests and consume canonical results and events. Only `model-catalog.ts` decides which provider a configured model belongs to and only `factory.ts` selects an adapter for it; only adapter modules know provider HTTP, credentials, wire fields, continuation details, or model-specific feature mapping. The canonical service surface is `complete`, `stream`, and `runAgent`; each adapter owns authentication and endpoint selection, request serialization and stream parsing, the provider file upload/deletion lifecycle, effort/reasoning mapping, structured-output and prompt-caching realization, tool-call/tool-result continuation, token estimation where the provider supports it, usage/stop-reason/error normalization, and its own opaque continuation state. The rules that bind every module here are in [inference/CLAUDE.md](../src/inference/CLAUDE.md).

| `audit-session-authority.ts`   | Strongly consistent state keyed by the stable signed audit identifier. The record also keeps the whole-session totals a worker without runs enforces its limits from, so a rollback still holds live sessions to them.
